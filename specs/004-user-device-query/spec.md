# Feature Specification: 用户设备信息与状态查询

**Feature Branch**: `004-user-device-query`

**Created**: 2026-09-07

**Status**: Draft — 2026-09-15 同步多步计划与查询确认边界；LangGraph4j 接入尚未实施，待独立规划。

**Input**: 用户通过自然语言查询本人已绑定设备的列表、名称、类型、型号及可获取的实时状态，AI 负责理解查询与组织结果，服务端负责权限和真实数据访问。

**Feature Map**: [五个 feature 总览](../README.md)。依赖[公共基础与统一意图计划器](../002-assistant-foundation/spec.md)，复用已有设备管理和外部设备客户端。

## Clarifications

### Session 2026-09-07

- 设备信息与状态查询独立于知识咨询、故障诊断和设备控制。设备绑定成功不等于该设备的所有运行状态均可查询。
- 延续既有绑定规则：稳定元数据保存在平台，设备运行状态按需从外部服务获取；不将失败的状态查询推断为确定离线。

### Session 2026-09-15

- 所有设备查询及请求在执行前均需用户确认，包括元数据、实时状态、诊断取证和控制后复检；复检作为独立查询步骤，不能由诊断或控制隐式读取。确认可在同一步骤设备、操作与参数未变且有效时供重试/恢复复用，每次请求仍重新校验权限和幂等条件。
- 查询作为有序计划的独立步骤，支持前序结果引用和条件分支；超时有限自动重试，明确失败、拒绝或重试耗尽停止整个计划并保留已有结果；服务重启后仅本人明确请求继续才恢复。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查询我的设备列表与信息 (Priority: P1)

用户询问已绑定哪些设备，或某台设备的名称、类型与型号，获得本人设备的准确信息。

**Why this priority**: 直接复用现有设备管理成果，提供自然语言查询价值。

**Independent Test**: 准备两名用户及各自绑定设备，确认查询设备列表、名称和型号，验证确认前不执行查询、确认后只返回当前用户数据。

**Acceptance Scenarios**:

1. **Given** 用户绑定了多台设备，**When** 询问“我有哪些设备”并确认该查询，**Then** 返回本人的设备列表，使用用户设置的显示名称，并提供已知类型和型号。
2. **Given** 用户尚未绑定设备，**When** 确认设备列表查询，**Then** 明确说明列表为空，并说明可按现有流程添加设备，不编造设备。
3. **Given** 本人绑定了暂不支持诊断的型号，**When** 确认查询其名称和型号，**Then** 正常返回稳定元数据，并区分该信息与诊断/控制支持能力。
4. **Given** 用户提供他人设备 ID、SN 或名称，**When** 请求查询，**Then** 拒绝越权且不泄露该设备详情或所有者。

### User Story 2 - 查询单台设备的实时状态 (Priority: P1)

用户询问“客厅灯亮度多少”“现在是否运行”，系统明确查询目标及范围，经用户确认后读取外部服务的实际状态。

**Why this priority**: 实时查询是独立能力，不应先要求用户描述故障。

**Independent Test**: 使用真实外部设备服务中的受支持灯泡，改变测试设备状态后重新查询，确认返回当前值且查询过程没有命令下发。

**Acceptance Scenarios**:

1. **Given** 唯一匹配的本人灯泡可读取亮度和运行状态，**When** 询问“客厅灯现在亮度多少”并确认该查询步骤，**Then** 返回本次读取的值和读取时间，不使用绑定时的旧状态。
2. **Given** 有多台设备符合“卧室灯”，**When** 查询该设备状态，**Then** 列出本人候选设备并澄清，在目标唯一前不读取设备实时状态。
3. **Given** 设备服务超时或返回错误，**When** 查询状态，**Then** 仅超时可在公共预算和有效确认范围内自动重试；明确错误、拒绝或重试耗尽停止整个计划，报告状态无法获取并保留已有结果，不推断设备离线。
4. **Given** 当前设备或字段不支持状态读取，**When** 查询该字段，**Then** 明确说明不支持或无数据，仍可返回已知元数据；不推导不存在的指标。
5. **Given** 查询步骤用于诊断证据或控制后复检，**When** 计划路由到该步骤，**Then** 独立展示目标与读取范围并等待确认，不复用另一查询或控制步骤的确认；读取结果供后续步骤或主图汇总引用。
6. **Given** 同一步骤超时或中断后恢复，**When** 查询内容未变且确认仍有效，**Then** 可复用确认并校验当前权限，已成功结果不重复执行；重启后本人请求继续前不读取设备。

### Edge Cases

- 本人设备列表可包含多台设备；实时读取以一台已明确设备为一个逻辑步骤，多设备请求拆为有序且分别确认的步骤。
- “亮度为 3”是状态事实，不能自动等同于故障；“查询亮度，低于 30 就调到 80”生成查询及条件控制步骤，各自确认；查询步骤不自行升级为控制。
- 用户绑定的设备在外部服务中已不可发现：保留绑定记录，不自动删除、重新绑定或创建设备。
- 状态部分字段缺失、类型不符合预期或响应不完整：明确指出无法确认的字段，不补造值。
- 用户身份在后续轮次失效或设备归属不再符合要求：重新校验并拒绝读取。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持自然语言查询本人设备列表和单台设备的稳定元数据，复用现有设备管理记录，不建立独立设备台账。
- **FR-002**: 系统 MUST 使用经服务端确认的当前用户身份限制查询范围；用户输入、模型选择的设备 ID 或 SN 均不能绕过归属检查，管理员也不能查询他人设备。
- **FR-003**: 单台设备实时查询 MUST 先定位唯一的本人目标；候选不唯一或线索不足时先澄清，无绑定或无匹配时返回明确提示。
- **FR-004**: 稳定信息 MUST 使用平台绑定记录中的用户显示名称及已知类型/型号等元数据；未支持诊断或控制的设备仍可查询其元数据。
- **FR-005**: 实时状态 MUST 在查询时从外部设备服务读取，并说明本次读取时间；MUST NOT 将绑定数据、历史对话或模型推测当作当前状态。
- **FR-006**: 系统 MUST 只返回外部服务实际提供且已支持解释的字段；首期验收覆盖已接入智能灯泡的亮度、色温和运行状态，缺失或不支持字段须明确提示。
- **FR-007**: 系统 MUST 区分查询成功、无匹配设备、字段不支持、设备不可发现和服务不可用；请求失败不等于设备确定离线，部分缺失不能伪装成完整成功。
- **FR-008**: 本能力 MUST 为只读能力；每个查询步骤执行前 MUST 按 002 FR-016 取得用户确认，覆盖元数据、实时状态、诊断取证与控制后复检。同一步骤内容未变且确认有效时可供超时重试或恢复复用，每次请求仍重新校验身份、归属、权限及幂等条件。MUST NOT 下发命令、自动修复、修改绑定或自行升级为控制。
- **FR-009**: 系统 MUST 通过 QuerySubGraph 执行查询，复用公共 AI Service、计划、会话与输出方式；AI 负责理解字段和组织结果，确定性节点在确认及校验后读取并验证数据。查询结果 MUST 对外展示并供后续步骤引用，AI MUST NOT 改写测得值的含义；完成后由主图推进计划。
- **FR-010**: 用户可见查询结果 MUST 与本人会话、本轮设备及读取时间关联留存，MUST NOT 将临时状态写回稳定设备元数据。
- **FR-011**: 系统 MUST 支持多设备元数据列表及单设备实时查询步骤，多设备实时需求由公共主图编排为有序步骤，支持条件与前序结果引用，不自动增删或循环步骤。仅超时可按公共有限预算自动重试；明确失败、拒绝或耗尽即停止整计划并保留已有结果。幂等、检查点及重启后本人明确继续遵循 002；不包含历史趋势、订阅监控或跨用户查询。

### Key Entities

- **设备绑定**: 复用平台设备记录，包含当前用户归属、唯一 SN、显示名称及稳定外部标识。
- **查询请求**: 查询范围、目标线索、请求字段、计划与稳定逻辑步骤标识及该步骤确认关联；设备候选来自当前用户授权范围。
- **状态读取结果**: 指定设备本次读取的字段值、读取时间及缺失/失败原因，与稳定元数据分开。
- **设备查询回答**: 经过校验的数据解释及可用性说明，不是诊断结论或控制请求。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 设备列表、单台元数据和实时状态验收场景全部返回与绑定记录或本次外部读取一致的结果。
- **SC-002**: 所有查询在有效确认及校验完成前、单台查询目标未澄清前，业务设备读取次数为零；越权设备详情泄露为零。诊断取证与控制后复检不得隐式绕过独立查询步骤。
- **SC-003**: 无数据、不支持字段、不可发现和服务失败样例全部给出对应提示，编造实时状态为零。
- **SC-004**: 全部查询场景的设备写操作与绑定记录变更次数为零；成功的实时回答全部带有本次读取时间。
- **SC-005**: 超时重试未突破配置上限，明确失败/拒绝后的重试和剩余步骤执行次数为零；已成功查询的重复提交或恢复复用原结果，重启后明确继续前的查询执行次数为零。

## Assumptions

- 002 提供账户、设备绑定、公共会话与路由；复用当前 `DeviceRegistryService`、`DeviceLocator`、设备归属校验和外部设备客户端，补齐自然语言字段查询与只读编排。
- 设备交互继续使用独立 deviceSimulator 服务；本项目不实现设备模拟器。首期状态验收限现有智能灯泡 LITE/LA001、LITE/LB001，其他已绑定型号至少可查询稳定元数据。
- 不要求先实现知识咨询、故障诊断或安全控制即可验收本 feature。各能力复用设备客户端与定位能力，避免通过“启动诊断流程”来查询状态。

## 2026-09-09 参数问答范围补充

设备查询不仅返回原始字段，也包括需要结合本人具体设备参数进行解释、比较、估算或提出建议的只读问题，例如“客厅灯当前亮度适合阅读吗”“根据我的灯的功率估算每天使用八小时的耗电量”。必须先确认该查询、验证归属并获取可用的真实参数；缺参数或估算条件时明确说明或追问，不编造。通用常识和不依赖本人设备的型号公开规格属于 003。只读参数问答本身不构成控制；含明确状态变更时由公共计划安排独立控制步骤。
