# Feature Specification: 公共基础与统一意图路由

**Feature Branch**: `002-assistant-foundation`

**Created**: 2026-09-07

**Status**: Implemented — 2026-09-08 实施完成并验收，见 [plan.md](plan.md) 与 [validation.md](validation.md)

**Input**: 复用当前用户控制、设备管理、基础 DTO、鉴权、会话与流式响应；Intent Router 和 AI Config MUST 基于 LangChain4j AI Service 方案重写，为四类对话能力提供统一入口。

**Feature Map**: [五个 feature 的范围、依赖与迁移映射](../README.md)。本 feature 负责公共基础，不负责四项能力的业务实现。

## Clarifications

### Session 2026-09-07

- 本次拆分按用户确认的五个 feature 执行；原有用户管理、SN 绑定和会话行为作为兼容基线。AI Service 重写是明确要求，不将已有底层模型调用视为已完成重写。
- 诊断只生成待确认控制请求；所有设备状态变更由安全设备控制 feature 统一处理。路由分类和模型输出均不构成操作授权。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在同一个对话入口使用四类能力 (Priority: P1)

用户在同一对话中咨询知识、查询本人设备、描述故障或提出控制请求，系统识别本轮意图并进入相应能力；模糊输入先澄清。

**Why this priority**: 统一入口和正确分流是四项能力共享的前置条件。

**Independent Test**: 对公共入口输入四类明确请求与模糊请求，用能力接收记录验证分流和上下文，无需实现各能力内部业务，也无需向设备下发命令。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 分别输入“什么是色温”“我的客厅灯现在亮度多少”“客厅灯为什么不亮”“把客厅灯亮度调到 80”，**Then** 分别进入知识咨询、设备查询、故障诊断、安全控制，诊断与控制不得合并为一个意图。
2. **Given** 无可用上下文，**When** 用户输入“帮我处理一下”，**Then** 系统追问具体目标，不读取或修改任何设备。
3. **Given** 同一会话上一轮已结束，**When** 用户提出另一类新问题，**Then** 重新识别本轮意图；最近 20 条历史消息可用于理解指代，旧结论或旧确认不得复用为本轮授权。
4. **Given** 模型返回未知分类、结构不合法或调用失败，**When** 本轮路由无法完成，**Then** 分别进入澄清或明确的服务失败响应，不默认进入控制流程。
5. **Given** 用户一次请求“查询亮度，太暗就调高”，**When** 无法确定单一待办理事项，**Then** 要求用户选择先办理的事项；不得把条件描述当作预先确认。

### User Story 2 - 继续使用已有账号与本人设备 (Priority: P1)

用户沿用已有注册、登录、注销、个人信息与设备添加/列表能力；管理员沿用已有用户管理能力。

**Why this priority**: 拆分需要保持已有用户数据与权限边界，避免重复建设基础功能。

**Independent Test**: 回归已有账号、令牌、管理员管理和 SN 绑定场景，验证原有用户与设备记录仍可使用。

**Acceptance Scenarios**:

1. **Given** 用户提交有效注册资料，**When** 注册、登录、查看本人信息并注销，**Then** 操作依次成功，响应不含密码，注销后的令牌无法继续访问。
2. **Given** 用户未登录、令牌失效或已被禁用，**When** 访问受保护能力，**Then** 拒绝访问；普通用户访问管理功能也被拒绝。禁用后再启用不会恢复已撤销的旧令牌。
3. **Given** 管理员已登录，**When** 分页、按账号或昵称搜索用户并禁用/启用用户，**Then** 保持原有能力；管理员同样无权访问他人的设备或对话。
4. **Given** 外部设备服务已存在可发现且未绑定的设备，**When** 用户提交有效 SN 和显示名称，**Then** 绑定到本人名下，使用用户显示名称并保存稳定元数据；平台不代建设备。
5. **Given** SN 已绑定、无效、不可发现或查询失败，**When** 请求添加，**Then** 区分绑定冲突、格式错误、未找到与服务不可用，新增记录为零且不泄露其他用户归属。
6. **Given** 可发现设备的型号尚不支持诊断，**When** 绑定并查看列表，**Then** 允许绑定、展示元数据和支持情况；绑定成功不代表已支持诊断或控制。

### User Story 3 - 保持会话与公共响应一致 (Priority: P1)

调用方继续使用已有会话和流式响应方式，用户能查看历史并继续提问。

**Why this priority**: 四项能力需要共享可追溯的对话上下文和可恢复的交互方式。

**Independent Test**: 在同一会话切换能力、等待输入、结束并重新提问，验证历史、流关闭和断线补查行为。

**Acceptance Scenarios**:

1. **Given** 正在处理本轮消息，**When** 有用户可见的回答或状态变化，**Then** 通过既有文本、状态、等待输入、结论和错误事件语义返回；内部分类、提示词和结构化推理不作为回答泄露。
2. **Given** 本轮进入等待输入或终态，**When** 处理结束，**Then** 关闭本次流；断线不补发历史事件，用户可补查会话状态和已保存消息。
3. **Given** 已有历史会话，**When** 查看列表或继续对话，**Then** 只可访问本人记录，长期保留历史；并发提交同一会话消息不会重复写入当前输入或串用其他用户上下文。
4. **Given** 合法的模型配置发生替换，**When** 启动并处理同一组路由请求，**Then** 使用所配置的模型且保持输出契约；无效配置明确报错，真实模式不得静默切换为模拟成功。

### Edge Cases

- 明确与四项能力无关的请求：说明服务范围；信息不足时澄清，不强行选取设备意图。
- 一个请求包含多台设备的写操作或多个独立意图：首期引导用户逐项办理，不自动生成批量或条件任务；本人设备列表查询不受此限制。
- 已有待确认操作时收到新问题：安全控制 feature 决定旧请求取消或失效；新的普通消息不得隐式确认旧操作。
- 登录过期、账号禁用、会话不属于本人、模型异常和断线均须给出明确结果，不能导致未经确认的设备写操作。
- SN 并发重复绑定必须保持全局唯一；运行状态不得因列表缓存而被当作权威实时状态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供统一的自然语言会话入口，并将明确请求分流到知识咨询、用户设备信息与状态查询、设备故障诊断、安全设备控制四项能力。
- **FR-002**: 系统 MUST 区分四种业务意图及无法确定的结果；原有合并诊断/控制的 `DEVICE_ACTION` 语义 MUST 被拆开。型号知识归知识咨询，明确的售后查询归诊断 feature 的售后引导分支，均不得因此触发设备写操作。
- **FR-003**: 系统 MUST 使用本轮输入和本人会话上下文识别意图；无法确定时追问；模型失败时报告失败。首期多个独立意图 MUST 先明确本轮办理事项，不实施自动任务拆解、条件执行或批量控制。
- **FR-004**: Intent Router 和 AI Config MUST 基于 LangChain4j AI Service 重写；统一创建和配置 AI Service，提供有明确分类/结构化输出契约的路由与分析能力，以及用户可见的回答能力。只声明未被实际调用的 AI Service 接口不满足要求。
- **FR-005**: AI 配置 MUST 外部化管理模型连接、模型选择及调用参数，复用现有配置入口；四项能力 MUST 复用统一配置与创建机制。真实模式 MUST NOT 静默模拟成功；明确测试模式可继续使用既有模拟 AI。
- **FR-006**: 路由与 AI 输出 MUST 仅作为候选业务输入；身份、设备归属、权限和可执行性 MUST 由服务端确定。知识/查询/诊断的 AI 调用 MUST NOT 获得绕过安全控制流程的设备写入口。
- **FR-007**: 系统 MUST 复用已有用户、设备、会话、消息和公共 DTO/响应契约，保留现有数据；仅为拆分所需补充字段或职责归位，MUST NOT 另建重复的用户或设备管理体系。
- **FR-008**: 系统 MUST 保持注册、登录、当前用户信息、注销及管理员列表/搜索/禁用/启用；新注册用户只能为普通用户。账号为 4–32 位字母、数字或下划线。注册密码须满足现有 8–64 位长度校验，同时包含英文字母和数字，且 UTF-8 编码后不得超过 72 字节；两次密码一致。超出限制 MUST 返回明确的参数错误，不得通过截断密码使其通过校验。昵称缺省取账号；密码安全存储且不出现在响应或日志中。
- **FR-009**: 系统 MUST 要求登录后使用四项能力，只允许访问本人设备和会话；普通用户不可访问管理功能。注销、过期或禁用后的令牌 MUST 失效，启用账号不得复活旧令牌；本地开发身份机制仅可通过显式测试/开发开关启用，生产关闭。
- **FR-010**: 系统 MUST 保持按 SN 绑定已有可发现设备的行为、SN 全局唯一和用户显示名称优先；保存外部设备 ID、SN、类型/型号编码与 ID、原始名称、显示名称和归属，MUST NOT 将设备运行状态或外部时间戳作为绑定元数据持久化。不支持诊断/控制的型号仍允许绑定。
- **FR-011**: 绑定失败 MUST 不新增或覆盖记录；非法 SN、未找到、重复绑定、外部服务不可用须分别给出原有明确错误语义，重复绑定错误不得泄露所有者。
- **FR-012**: 对话与用户可见消息 MUST 长期保留，支持本人历史列表、详情、新建与继续；结束后新问题重新路由，模型仅使用最近 20 条历史窗口加当前输入一次；各用户、会话与处理轮次 MUST 隔离。
- **FR-013**: 系统 MUST 保持现有会话 POST 流式响应及 GET 补查契约：用户可见文本逐步返回，等待输入或终态关闭本轮流，断线不补发；公共错误与状态事件在四项能力中语义一致。
- **FR-014**: 系统 MUST 保留输入、路由、澄清、关键状态和结论的追溯关联；只记录必要信息，MUST NOT 记录密码、令牌、模型密钥或向用户泄露内部提示词。

- **FR-015**: 公共基础 MUST 复用已有设备定位、归属检查、客户端/适配契约与设备互斥机制，供各能力调用；各能力负责本轮业务校验及占用生命周期，MUST NOT 为拆分复制平行的设备接入或锁实现。

### Key Entities

- **用户与设备绑定**: 复用现有账号、角色、SN 唯一性、设备归属和稳定元数据。
- **对话与处理轮次**: 对话长期保留，一轮对应一次用户请求的处理；待确认操作与当前轮次关联，不等于整个对话永久授权。
- **意图识别结果**: 四能力分类或待澄清结果，可包含理解所需的目标线索；不是已验证的设备身份或操作权限。
- **公共请求/响应及消息**: 复用原有 DTO、展示对象和事件类型；新增能力使用同一公共交互契约。
- **AI 能力配置**: 配置统一的模型接入、调用参数与能力创建方式，敏感值从环境注入。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 验收样例中四类明确请求全部进入正确能力；全部模糊、非法分类、失败和复合控制样例均不产生设备写调用。
- **SC-002**: 已有用户、管理员、SN 绑定和历史会话回归场景全部通过，原有有效用户与绑定记录继续可用。
- **SC-003**: 未登录/失效身份、越权设备/会话及普通用户管理请求的拒绝率为 100%；响应或日志中的凭据泄露为零。
- **SC-004**: 会话跨能力、跨轮次、等待、终态和断线补查场景全部保持正确关联；重复保存当前消息及用户间上下文串用为零。
- **SC-005**: 有效配置切换与无效配置失败场景均可验证；四项能力接入公共入口不需要重建用户、设备或会话体系。

## Assumptions

- 依赖与目录约束遵循[章程](../../.specify/memory/constitution.md)：AI Service 创建工厂在 `ai/factory`，AI 结构化输出在 `ai/model`，AI 分类枚举在 `ai/model/enums`；业务枚举在 `domain/enums`，DTO 在 `domain/dto`，VO 在 `domain/vo`，全局常量在 `constant`，工具在 `utils`。具体接口、类迁移和装配方式在本 feature 的 plan 中定义。
- 当前可复用代码入口为 `controller`、`service/user`、`core/security`、`core/device`、`core/session`、`domain/dto`、`domain/message`；这是复用依据，不表示全部满足新验收要求。
- 当前 `config/LangChain4jConfig`、`core/routing/IntentClassifier` 和 `domain/enums/Intent` 是重写/调整对象；已有底层模型调用与手动解析不视为完成 AI Service 方案。
- 仅规划现有后端 API 能力；不要求重做仓库已有前端，不增加角色修改、他人密码重置、设备代创建、批量控制或跨会话长期偏好记忆。
- 四能力处理器的内部实现分别在其他 feature 交付；本 feature 可独立验收路由及公共行为，不以四能力全部实现为完成前提。
