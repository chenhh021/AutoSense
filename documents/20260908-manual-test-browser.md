# 002 公共基础与统一意图路由 — 浏览器手动测试样例

**日期**: 2026-09-08
**适用**: 在前端页面手动操作，验证统一意图路由的各个分支、会话状态标签、用户管理与设备管理。
**重要背景**: 002 只交付公共编排与路由;**知识/设备查询/诊断/控制四个能力的业务处理器由 003/004/005 接入**，本期所有能力分支的预期结果都是"该能力暂未接入"，这是**正确行为**而非缺陷。公共路由本身不做任何设备读写。

---

## 0. 测试前提

### 0.1 服务启动

| 项 | 值 |
| --- | --- |
| 后端 | `LLM_MODE=mock`、`SQL_INIT_MODE=always`(首次建表，之后可改回 `never`)，其余默认；`./mvnw.cmd spring-boot:run`，端口 **8180** |
| 前端 | `cd frontend && npm run dev`，浏览器访问 **http://localhost:5173** |
| 依赖 | MySQL 3306、Redis 6379 可用(默认值即可) |

已有数据库在启动新版后端前，先备份并执行
`scripts/migration/20260907-assistant-processing.sql`，目标数据库须与 `MYSQL_URL` 一致。
该脚本只为 `repair_session` 补齐 `processing_message_id`、`processing_deadline_at`，可重复执行。
`SQL_INIT_MODE=always` 只会创建缺失的表，**不会升级已有表**，不能替代增量迁移。
漏迁移会导致创建对话、读取会话列表出现 `BadSqlGrammarException`（MySQL 1054）。
后端现在会在 SQL 初始化之后检查这两个字段，缺失时停止启动并提示迁移路径。

### 0.2 测试账号

| 账号 | 密码 | 角色 | 来源 |
| --- | --- | --- | --- |
| `admin` | `admin123` | 管理员 | 种子数据自动预置(data.sql，重复启动幂等) |
| `testuser01` | `pass1234` | 普通用户 | 注册页自助注册 |
| `testuser02` | `pass1234` | 普通用户 | 注册页自助注册(用户管理用例的禁用/启用对象) |

### 0.3 设备前提

- **路由分支样例(第 1~10 用例)不要求已绑定设备**——公共路由零设备读写，这是设计约束。
- 设备管理用例(第 16~19 用例)依赖外部 deviceSimulator(仓库根《后端接口说明.md》中的模拟器服务):有模拟器时可绑定真实 SN(13 位，如 `LA00100000001`);**没有模拟器时绑定预期失败**，同样属于正确行为。

### 0.4 界面定位

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| 对话 | 控制台 → 对话(`/console/chat`) | 发消息、看流式回复/追问/错误 |
| 会话 | 控制台 → 会话(`/console/sessions`) | 会话列表与**状态标签** |
| 设备 | 控制台 → 设备(`/console/devices`) | 设备列表、添加、删除 |
| 用户管理 | `/admin/users`(仅管理员可见) | 用户列表、搜索、禁用/启用 |

会话列表的状态标签直接显示后端状态原文:`CLARIFYING`(等待澄清)、`COMPLETED_ANSWERED`(已回答)、`FAILED_REQUEST`(失败可续聊)等。

## 2. 路由与会话用例

### 用例 1:意图不明 → 澄清追问(CLARIFY)

- **前提**:已登录 testuser01，位于对话页(空白新对话)
- **操作**:输入 `你好`，回车发送
- **预期**:
  - AI 气泡显示追问:`您好，请问我有什么可以帮您的吗？`
  - 地址栏自动带上会话 ID(路由变为 `/console/chat/{id}`)
  - 切到会话页：该会话状态标签为 **`CLARIFYING`**

### 用例 2:组合意图 → 澄清追问(COMPOSITE)

- **操作**:新开对话，输入 `如果灯泡不亮就关闭它`
- **预期**:与用例 1 相同的澄清追问;会话标签 `CLARIFYING`
- **原理**:条件式/多意图输入被识别为组合请求，路由要求用户拆成单轮单项

### 用例 3:超出范围 → 直接结论(OUT_OF_SCOPE)

- **操作**:新开对话，输入 `给我讲个笑话`
- **预期**:
  - AI 气泡直接显示:`AutoSense 可以帮助咨询产品知识、查询您的设备、诊断设备问题和安全地控制设备。`
  - 无追问；会话页标签为 **`COMPLETED_ANSWERED`**

### 用例 4:知识咨询(KNOWLEDGE,能力未接入)

- **操作**:新开对话，输入 `智能灯泡寿命多久?`
- **预期**:
  - AI 气泡显示:`出错了：该能力暂未接入，请稍后再试。`
  - 会话页标签为 **`FAILED_REQUEST`**(终态失败，可继续发消息开启新一轮)

### 用例 5:设备查询(DEVICE_QUERY,能力未接入)

- **操作**:新开对话，输入 `列出我的所有设备`
- **预期**:同用例 4 的错误气泡与 `FAILED_REQUEST` 标签
- **注意**:即使已绑定设备也应如此——能力处理器属 004，公共路由不代查设备

### 用例 6:故障诊断(DIAGNOSIS,能力未接入)

- **操作**:新开对话，输入 `我的灯泡不亮了`
- **预期**:同用例 4 的错误气泡与 `FAILED_REQUEST` 标签

### 用例 7:售后网点(DIAGNOSIS/AFTERSALES,能力未接入)

- **操作**:新开对话，输入 `附近有哪些售后网点?`
- **预期**:同用例 4 的错误气泡与 `FAILED_REQUEST` 标签

### 用例 8:设备控制(CONTROL,能力未接入)

- **操作**:新开对话，输入 `打开客厅灯`
- **预期**:同用例 4 的错误气泡与 `FAILED_REQUEST` 标签
- **安全断言**:全程没有任何设备被读写(模拟器侧调用计数为 0)——AI 输出不构成设备写授权

### 用例 9:澄清后续聊(CLARIFYING → 新一轮路由)

- **前提**:用例 1 的 `CLARIFYING` 会话
- **操作**:进入该会话，接着输入 `列出我的所有设备`
- **预期**:
  - 本轮重新路由到设备查询，AI 气泡显示 `出错了：该能力暂未接入，请稍后再试。`
  - 历史消息完整保留(原"你好"与澄清追问仍在上文)
  - 会话标签从 `CLARIFYING` 变为 `FAILED_REQUEST`

### 用例 10:历史补查与会话列表

- **操作**:会话页点击任一历史会话进入
- **预期**:
  - 消息按时间升序完整展示(用户右蓝/助手左灰)
  - 与实时对话时看到的内容逐字一致
  - 会话列表每条显示状态标签，与进入后的会话状态一致

## 3. 用户管理用例(管理员)

### 用例 11:普通用户访问用户管理 → 403

- **前提**:已登录 testuser01(普通用户)
- **操作**:地址栏直接访问 `http://localhost:5173/admin/users`
- **预期**:跳转到 403 页面，看不到用户列表；导航中也不出现用户管理入口

### 用例 12:管理员查看用户列表与搜索

- **操作**:退出后以 `admin` / `admin123` 登录，进入用户管理页(`/admin/users`)
- **预期**:
  - 列表包含 `admin`、`testuser01`、`testuser02`;右上角标签显示 `共 N 位用户`
  - 角色标签:`admin` 行为蓝色 **管理员**,其余为 **普通用户**
  - 状态标签均为绿色 **正常**
  - `admin` 所在行的操作列显示 `当前账号不可操作`(禁止禁用自己)
  - 搜索框输入 `testuser01` 点搜索 → 仅剩该用户;清空后恢复
  - 关闭「包含已禁用用户」开关 → 列表过滤掉已禁用用户(若有)

### 用例 13:禁用用户 → 其全部令牌立即失效

- **前提**:testuser02 在**另一个浏览器**(或隐身窗口)中保持已登录状态
- **操作**:admin 在用户管理页对 testuser02 点 **禁用**，确认弹窗(`确定禁用该用户吗？其所有登录令牌将立即失效。`)
- **预期**:
  - admin 侧提示 `用户已禁用，现有令牌已失效`,testuser02 状态标签变为红色 **已禁用**
  - testuser02 侧任意下一次操作(发消息/刷新会话列表)→ 鉴权失效，跳回登录页
  - testuser02 用原账号密码重新登录 → **登录失败**(禁用账号与密码错误统一口径，不区分提示)

### 用例 14:启用用户 → 旧令牌不复活，需重新登录

- **操作**:admin 对 testuser02 点 **启用**，确认弹窗
- **预期**:
  - 提示 `用户已启用，需要重新登录`,状态标签恢复绿色 **正常**
  - 启用**不会**让禁用前的旧令牌复活:testuser02 必须重新登录，登录后功能恢复
  - 重新登录后的会话历史(002 之前产生的会话)仍完整可见

## 4. 设备管理用例

### 用例 15:设备列表空态与搜索

- **前提**:已登录 testuser01，未绑定任何设备
- **操作**:进入控制台 → 设备页
- **预期**:
  - 列表空态文案:`暂无设备，点击右上角「添加设备」创建`
  - 顶部有「按设备名称搜索」输入框与「添加设备」按钮

### 用例 16:添加设备 — 参数校验与无模拟器失败

- **操作**:点「添加设备」,依次提交:
  1. SN、名称都留空 → 提示 `请输入设备 SN 和名称`
  2. SN 填 `LA001`(非法格式)、名称 `客厅灯` → 提示 `添加设备失败，请检查 SN 是否正确`(SN 须为 13 位：4 位大写字母/数字 + 9 位数字)
  3. SN 填 `LA00100000001`(合法格式)、名称 `客厅灯`,**无模拟器环境** → 提示 `添加设备失败，请检查 SN 是否正确`(设备服务不可用，零数据落库)
- **预期**:以上三种情况列表仍为空；后端日志无 SN 原文

### 用例 17:添加设备成功(需要模拟器)

- **前提**:deviceSimulator 已启动，且存在 SN 为 `LA00100000001` 的在线灯泡
- **操作**:添加设备，SN `LA00100000001`、名称 `客厅灯`
- **预期**:
  - 提示 `添加设备成功`,列表出现该设备
  - 列展示：名称 `客厅灯`、类型 `smart_bulb`、型号 `LA001`、SN、`在线`(绿色标签)
  - 名称搜索框输入 `客厅` → 列表过滤到该设备;输入其他关键字 → 空

### 用例 18:重复绑定同一 SN(需要模拟器)

- **操作**:再次添加 SN `LA00100000001`(同账号或 testuser02 账号均可)
- **预期**:提示添加失败(SN 全局唯一，不允许重复绑定);列表中仍只有一台

### 用例 19:删除设备(已知差距)

- **操作**:对已绑定设备点「删除」并确认
- **预期(如实记录)**:提示 `删除设备失败`——**后端本期未提供删除接口**,前端按钮为预留功能。此为已知差距，不算回归缺陷;如需该能力应另行立项

## 6. 发送中并发(界面约束说明)

消息发送期间"发送"按钮处于 loading 禁用态，同一窗口无法再发；如用两个浏览器标签页对同一会话并发发消息，后到的一轮预期收到 `出错了` 类错误提示(后端 `SESSION_BUSY`)，且会话消息数不多出一条。此项为后端并发守卫的界面体现，观察即可，不作硬性断言。

## 7. 会话删除用例

### 用例 21:删除已完成会话 → 列表移除且补查 404

- **前提**:已登录 testuser01，会话页存在至少一条已完成会话(如用例 3 产生的 `COMPLETED_ANSWERED`)
- **操作**:会话页对该会话点「删除」,确认弹窗(`确定删除该对话吗？`)中点「删除」
- **预期**:
  - 提示 `删除成功`,该会话从列表中消失
  - 直接访问该会话地址(`/console/chat/{id}`)→ 会话不存在(后端 404 `SESSION_NOT_FOUND`)
  - 再次删除同一会话(如通过另一个已打开的标签页)→ 提示 `删除对话失败`,不假成功

### 用例 22:处理中会话禁止删除(观察项)

- **前提**:一条正在流式输出中的会话(发送消息后回复尚未结束)
- **操作**:发送期间在另一个标签页的会话页对该会话点「删除」并确认
- **预期**:提示 `删除对话失败`(后端 409 `SESSION_BUSY`);会话仍在列表中，待处理结束后可正常删除。此项为后端忙守卫的界面体现，观察即可

## 8. 日志核查点(后端控制台)

执行上述用例期间，后端日志应满足:

- 每条会话日志带 `sessionId=` / `messageId=` 等 MDC 字段，多会话交错时不串号
- **不出现**:密码原文、Bearer 令牌值、prompt 模板正文、用户消息的完整对话内容、设备 SN 逐项明细(设备列表只打 count/onlineCount 汇总)
- 路由与用户操作可见英文事件，如 `AI call completed: operation=intent-classify`、`User operation completed: operation=disable, result=DISABLED`
