# 设备操作接口说明

本文档描述 deviceSimulator 提供的**设备操作接口**（按设备 SN 寻址的 get / get_list / set / action）。这些接口面向设备接入方，行为完全由各型号的能力配置文件（`config/device/{设备类型}/{型号}.json`）驱动。

## 1. 接口概述

| 项目 | 说明 |
|------|------|
| 默认 Base URL | `http://localhost:8080` |
| 数据格式 | JSON（`Content-Type: application/json`） |
| 请求方法 | 全部为 `POST` |
| 认证 | 当前版本无需认证 |

接口一览：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/device/{sn}/get` | 查询单个设备的全部可获取属性 |
| POST | `/device/get_list` | 按 SN 列表批量查询设备属性 |
| POST | `/device/{sn}/set` | 设置单个设备的一个或多个属性（原子生效） |
| POST | `/device/{sn}/action` | 调用单个设备的一个动作 |

## 2. 通用规则

### 2.1 设备可发现性

只有处于 **运行中（running）** 状态的设备可以被操作。已停止（stopped）、离线中（offline，重启/固件升级后的短暂离线窗口）或不存在的 SN，统一返回 `404 NOT_FOUND`。

SN 格式：`^[A-Z0-9]{4}[0-9]{9}$`（前 4 位类型代号 + 9 位数字）。格式非法返回 `400 INVALID_REQUEST`。

### 2.2 模拟失败

每个设备可单独配置失败概率（`failure_probability`，0-100，默认 0）。`set` 和 `action` 接口按该概率模拟真实设备的随机失败：

- 失败时 **HTTP 状态码仍为 200**，响应体 `success` 为 `false`，并带 `error.code = "SIMULATED_FAILURE"`。
- `get` / `get_list` 不受失败概率影响。

### 2.3 动作延迟

`action` 接口在返回前会等待设备配置的动作延迟（`action_delay_seconds`，默认 10 秒），无论动作成功或失败都会等待。

### 2.4 reboot / firmware_upgrade 副作用

- `reboot` 成功后：设备进入 **离线（offline）** 状态，随机 1 ~ `offline_max_seconds` 秒（默认上限 60 秒）后自动恢复上线。离线期间所有操作接口返回 404。
- `firmware_upgrade` 成功后：同样的离线-上线周期，且上线后固件版本变更为随机值：日期部分为 2020-2030 年间的随机日期，版本号为随机 `x.y.z`（例如 `20271214-3.8.7`）。
- 若设备在离线窗口内被停止或删除，则不会恢复上线，待生效的固件版本变更一并丢弃。

### 2.5 通用错误响应

非 2xx 响应统一为：

```json
{
  "code": "ERROR_CODE",
  "message": "错误描述",
  "details": {}
}
```

| HTTP 状态码 | code | 触发场景 |
|-------------|------|----------|
| 400 | `INVALID_REQUEST` | 请求体非法、SN 格式错误、属性名未知、属性值类型/枚举/范围校验失败、动作未在能力文件中声明 |
| 404 | `NOT_FOUND` | 设备不存在、已停止或离线中 |
| 200 | `SIMULATED_FAILURE`（在 `error.code` 内） | 按设备失败概率模拟的操作失败，仅出现于 set / action |

## 3. 查询单个设备属性

`POST /device/{sn}/get`

请求体：无（可为空）。

返回设备能力文件中定义的**全部 GET 属性**，外加两个系统属性：`online`（由运行状态计算）和 `firmware_version`（取自设备档案）。

### 响应

```json
{
  "sn": "LITE123456789",
  "success": true,
  "properties": {
    "power": true,
    "brightness": 50,
    "color_temperature": 4600,
    "online": true,
    "signal_strength": -45,
    "firmware_version": "20250101-1.0.1"
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `sn` | string | 设备 SN |
| `success` | boolean | 固定为 `true` |
| `properties` | object | 全部可获取属性，键集合与能力文件一致 |

各型号 GET 属性键集合：

| 型号 | 属性 |
|------|------|
| MJDP09YL（单色智能灯泡） | power, brightness, color_temperature, online, signal_strength, firmware_version |
| MJDPL01YL（彩色智能灯泡） | power, brightness, color, online, signal_strength, firmware_version |
| KFR035GW（空调） | power, mode, current_temperature, target_temperature, fan_speed, swing, eco_mode, sleep_mode, compressor_status, error_code, filter_life, online, firmware_version |
| BLJ48WD240200PV（空气净化器） | power, mode, fan_speed, pm25, air_quality, temperature, humidity, filter_life, motor_status, error_code, child_lock, display_brightness, online, firmware_version |

## 4. 批量查询设备属性

`POST /device/get_list`

### 请求

```json
{
  "sns": ["LITE123456789", "AIRC000000001", "LITE000000000"]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sns` | string[] | 是 | 非空 SN 数组，元素不能为空字符串 |

### 响应

`results` 顺序与输入 `sns` 一一对应；**逐项容错**——单个 SN 失败不影响其他项：

```json
{
  "results": [
    { "sn": "LITE123456789", "success": true, "properties": { "power": true, "...": "..." } },
    { "sn": "AIRC000000001", "success": false, "error": { "code": "NOT_FOUND", "message": "device not found or not running" } },
    { "sn": "LITE000000000", "success": false, "error": { "code": "INVALID_REQUEST", "message": "invalid serial number" } }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `results[].sn` | 对应的输入 SN |
| `results[].success` | 该项是否查询成功 |
| `results[].properties` | 成功时的属性对象（同单设备 get） |
| `results[].error` | 失败时的错误，`code` 为 `NOT_FOUND` 或 `INVALID_REQUEST` |

## 5. 设置设备属性

`POST /device/{sn}/set`

请求体为**扁平的属性键值对**，一次可设置多个属性。服务端先对全部属性做合法性校验（属性名必须在能力文件 SET 列表中，值须满足类型/枚举/范围约束），**全部通过才一并应用（原子）**，任一非法则整体拒绝、不做任何修改。

### 请求示例

```json
{
  "power": true,
  "brightness": 80,
  "color_temperature": 4000
}
```

各型号可设置属性及约束：

| 型号 | 属性 | 类型 | 约束 |
|------|------|------|------|
| MJDP09YL | power | BOOLEAN | true / false |
| | brightness | INTEGER | 0 - 100（%） |
| | color_temperature | INTEGER | 2700 - 6500（K） |
| MJDPL01YL | power | BOOLEAN | true / false |
| | brightness | INTEGER | 0 - 100（%） |
| | color | OBJECT | `{"red":0-255,"green":0-255,"blue":0-255}`，三个子属性均必填 |
| KFR035GW | power | BOOLEAN | true / false |
| | mode | STRING | AUTO / COOL / HEAT / DRY / FAN |
| | target_temperature | NUMBER | 16 - 30（°C） |
| | fan_speed | STRING | AUTO / LOW / MEDIUM / HIGH |
| | swing | STRING | OFF / VERTICAL / HORIZONTAL / AUTO |
| | eco_mode | BOOLEAN | true / false |
| | sleep_mode | BOOLEAN | true / false |
| BLJ48WD240200PV | power | BOOLEAN | true / false |
| | mode | STRING | AUTO / SLEEP / MANUAL |
| | fan_speed | STRING | LOW / MEDIUM / HIGH |
| | child_lock | BOOLEAN | true / false |
| | display_brightness | INTEGER | 0 - 100（%） |

### 响应

成功（HTTP 200）：

```json
{
  "success": true,
  "properties": {
    "power": true,
    "brightness": 80,
    "color_temperature": 4000
  }
}
```

`properties` 为本次实际修改后的属性值。

模拟失败（HTTP 200，按设备 `failure_probability` 触发）：

```json
{
  "success": false,
  "error": { "code": "SIMULATED_FAILURE", "message": "simulated device operation failure" }
}
```

校验失败（HTTP 400）：`message` 中指明出错的属性名及原因。

## 6. 调用设备动作

`POST /device/{sn}/action`

每次只能调用一个动作；动作名必须在能力文件的 ACTION 列表中。接口在返回前等待设备的动作延迟（默认约 10 秒）。

### 请求

```json
{
  "action": "reboot",
  "parameters": {}
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 是 | 动作代码 |
| `parameters` | object | 否 | 保留字段，当前各动作均无入参，传 `{}` 即可 |

### 响应

```json
{
  "action": "reboot",
  "success": true
}
```

模拟失败时 `success` 为 `false` 且带 `error.code = "SIMULATED_FAILURE"`（HTTP 200）。动作未在能力文件中声明时返回 400。

### 各型号动作

| 型号 | 动作 | 特殊副作用 |
|------|------|-----------|
| MJDP09YL / MJDPL01YL | reboot, firmware_upgrade | 见 §2.4 离线周期与固件版本变更 |
| KFR035GW | reboot, self_diagnosis, clear_error, reset_filter_life, firmware_upgrade | reboot / firmware_upgrade 见 §2.4；clear_error 清除 error_code；reset_filter_life 将 filter_life 重置为 100 |
| BLJ48WD240200PV | reboot, self_diagnosis, reset_filter_life, sensor_calibration, firmware_upgrade, factory_reset | 同上；factory_reset 将全部状态恢复为出厂默认值 |

## 7. 相关管理接口

设备的创建、启停、失败概率/动作延迟/离线上限等参数配置通过管理接口完成（`/api/v1/devices` 系列，详见《后端接口说明.md》）。设备操作接口只接受运行中设备，请先通过管理接口启动设备。
